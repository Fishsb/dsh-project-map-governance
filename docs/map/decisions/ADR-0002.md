# ADR-0002：引擎并入插件仓库：单一仓库承载契约层 + 引擎（engine/ 子目录）

> 状态：accepted ｜ proposed ｜ deprecated ｜ superseded

## 背景

引擎（`scripts/*.mjs`）作为体系单一事实源，长期散落在无版本控制的 skill 目录（`C:\Users\lk\.dsh\skills\project-map-governance`），不受 git/CHANGELOG/自治理约束——修改无 diff、无回滚、无审计痕迹（ADR-0001 确立的"引擎独立于插件仓"恰好让引擎失去版本保护）。尝试为其单独建仓后，发现两个仓库维护成本高、且引擎与插件契约本属同一发布单元（插件薄契约依赖引擎行为）。

## 决策

撤销 ADR-0001 的"引擎不在插件仓库"约束，改为**单一仓库双目录**：

```
dsh-project-map-governance-plugin/
├── src/ + package.json    插件契约层（DSH 工具注册）
├── engine/                引擎源码：SKILL.md + scripts/*.mjs + governance.schema.json + test/smoke.mjs
├── scripts/build.sh       插件构建脚本（与 engine/scripts 分离）
└── docs/map/              治理层（现治理整个插件仓，含 engine/）
```

引擎自定位基于 `import.meta.url`（向上两级解析 SKILL_DIR），故 `engine/` 子目录下运行/安装行为不变。skill 目录 `C:\Users\lk\.dsh\skills\project-map-governance` 降级为**运行部署副本**（从本仓 engine/ 同步），不再承担源码权威。

## 后果

正面：引擎获得 git 版本控制 + CHANGELOG + 自治理（docs/map 覆盖 engine/）；契约层与引擎同一发布节奏、同一仓库可追溯；消除"引擎无家可归"。

成本/注意：ADR-0001 的"引擎独立演进、插件不随引擎发版"解耦被放弃——今后引擎改动与插件发版同仓关联；hook/AGENTS 生成时会硬编码引擎实际安装路径（`engine/` 或 skill 副本），迁移项目需重跑 init 或手动改 hook；README/CLAUDE/AGENTS 的"引擎不在本仓库"表述需全部更新。

## 替代方案

- **引擎单独建仓（ADR-0001 + 独立 engine 仓）**：曾尝试，双仓维护 + 推送/发布双轨成本高，且 engine 仓与插件仓强耦合（插件必须指向某引擎版本）。否决。
- **引擎留在 skill 目录不建仓**：无版本控制风险持续。否决。
- **引擎并入插件 src/**：引擎是 Node stdlib 脚本非 TS 插件源码，混入 src 会污染插件编译/打包。否决（用 engine/ 子目录隔离）。
